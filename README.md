# 青龙多市场行情订阅

在各自的交易时段，每半小时获取一次关注品种的最新行情，通过青龙已配置的通知渠道发送。支持上金所黄金、沪深北 A 股、沪深场内 ETF、港股、南向港股通、美股和加密货币现货。同一时点合并为一条消息。

默认只关注上金所 Au99.99。所有品种在一个 `MARKET_ALERT_CONFIG` 中配置，旧版黄金和 A 股配置可直接继续使用。首次使用只需安装依赖、添加仓库订阅；关注其他品种时再填写列表。**白名单、黑名单和依赖文件均可留空**，仓库只有一个会被青龙默认识别的脚本，自动生成一个行情任务。

## 推送规则

所有时间均为北京时间，开盘、收盘时点也会播报。

| 市场 | 时段 | 推送频率 |
| --- | --- | --- |
| A 股及国内 ETF | 09:30—11:30、13:00—15:00 | 每半小时一次，共 10 次/交易日 |
| 上金所黄金日盘 | 09:00—15:30 | 每半小时一次，共 14 次/日盘 |
| 上金所黄金夜盘 | 20:00—次日 02:30 | 每半小时一次，共 14 次/夜盘，凌晨照常 |
| 港股 | 09:30—12:00、13:00—16:00；半日市至 12:00 | 每半小时一次，正常交易日 13 次 |
| 港股通（南向） | 与港股交易时段相同，使用独立的港股通日历 | 每半小时一次 |
| 美股常规时段 | 夏令时 21:30—次日 04:00；冬令时 22:30—次日 05:00；提前收市日按日历缩短 | 每半小时一次，正常交易日 14 次 |
| 加密货币现货 | 全天 24 小时，含周末和节假日 | 每半小时一次，每天 48 次 |

每次只播报当时仍在交易的关注品种。均已休市时，不获取行情、不发通知。配置加密货币后，每天都会全天推送，包括凌晨。上金所正常周五的夜盘延续至周六 02:30，周日晚上不开夜盘；法定节假日前的停夜盘日期单独处理，行政补班周末也不会误判为交易日。

黄金、A 股、港股及港股通内置各交易所公布的 **2026 年**日历。其他年份会尝试读取各自官网的全年公告或港交所年度 CSV，识别成功后缓存。官网尚未公布、访问失败或格式改变时，该市场暂停播报，并在日志说明原因；其他市场继续播报。日历不会退化为简单的周一至周五判断。

美股使用 `exchange-calendars` 的 XNYS 日历与纽约时区，自动处理夏令时、周末、节假日及提前收市，覆盖美国主要股票市场的常规时段；不含盘前、盘后、期权或期货。美股交易日按纽约日期显示，行情时间统一换算为北京时间。港股播报连续交易时段，收市竞价结束价可能晚于 16:00 的最后一次播报。

港股通指**南向港股通**，按港交所公布的独立交易日历运行，例如港股开市、内地休假的日期可能不推送。它与直接交易港股使用同一只股票的原币行情；不会转换成人民币结算价，也不自动核验股票是否仍在最新港股通标的名单。同一只港股在 `hk_stocks` 和 `hk_connect` 中二选一配置，重复会报错。

特殊临时休市可以通过配置覆盖；美股临时变更需更新日历依赖或添加休市覆盖。已缓存的年度日历发生变更时，需添加覆盖或删除对应缓存后重新获取。

## 在青龙中使用

### 1. 安装 Python 依赖

需要 **Python 3.11.5 或更高版本**。在青龙「依赖管理 → Python3」中分别添加并安装：

```text
akshare==1.20.63
requests>=2.32,<3
exchange-calendars==4.13.3
```

安装成功后再运行行情任务。已有用户要启用美股，只需额外安装 `exchange-calendars==4.13.3`，它会带上所需时区数据；其他新增市场不需要这项依赖。AKShare 和交易日历依赖 pandas 等组件，首次安装可能需要一些时间。仓库中的 `requirements.txt` 用于本地或终端安装，订阅本身不会自动安装 Python 依赖。

### 2. 添加仓库订阅

在青龙「订阅管理」中新建公开仓库订阅，填写仓库链接：

```text
https://github.com/whwnow/qinglong-market-alert.git
```

保持自动添加任务开启，白名单、黑名单、依赖文件和分支留空，其余使用默认值即可。如果面板要求填写文件后缀，填 `py`。

保存后执行一次订阅，会自动创建「黄金与A股行情播报」任务。时间规则已经写在脚本中，无需手动创建任务或填写运行命令：

```cron
0,30 * * * *
```

每小时的 00、30 分运行，脚本自动跳过休市时段。订阅自身的更新频率可以保持你平时使用的设置，它只负责拉取代码。请确认青龙系统时区为 **Asia/Shanghai**，通知渠道已配置可用。

通知优先通过 `QLAPI.systemNotify` 直接使用青龙「系统设置 → 通知设置」保存的配置，并检查返回的成功码。无需把推送密钥再填一遍到环境变量。缺少此接口的旧环境才使用 `QLAPI.notify`、`__ql_notify__.send` 或 `notify.send`；这些脚本通知使用的是脚本通知变量，与面板保存的配置可能不同，未配置有效渠道会明确报错。

**需要验证时，直接点击任务的「运行」即可。** 脚本识别青龙的手动执行标记后，会立即检查全部关注品种和通知；休市、非整点也可以检查，无需添加命令参数。手动检查的消息标题会注明「手动检查」，休市报价会注明状态，并且不占用自动播报记录。正常定时执行仍按交易时段过滤。

### 3. 配置关注品种

默认只关注 Au99.99，不需要填写配置。要关注股票，在青龙环境变量中添加 **`MARKET_ALERT_CONFIG`**，值例如：

```json
{"gold": ["Au99.99"], "stocks": ["600519", "000001"]}
```

代码替换成自己的关注列表即可。不要加 `export`，不要在最外层再包一层引号。

关注多个市场时，仍然只修改这个环境变量：

```json
{
  "gold": ["Au99.99"],
  "stocks": ["600519", "000001", "510300", "159915"],
  "hk_stocks": ["00700"],
  "hk_connect": ["09988"],
  "us_stocks": ["AAPL", "TSLA", "BRK.B"],
  "crypto": ["BTC/USDT", "ETH/USDT"]
}
```

| 字段 | 品种及代码示例 | 报价单位 |
| --- | --- | --- |
| `gold` | 上金所合约，如 `Au99.99` | 人民币元/克 |
| `stocks` | 沪深北 A 股及沪深 ETF，如 `600519`、`000001`、`510300`、`159915` | 股票：元/股；国内 ETF：元/份，保留三位小数 |
| `hk_stocks` | 港股，如 `00700`、`hk00700`、`00700.HK`；也接受 `700`，自动补零 | 按来源币种，通常港元/股；人民币柜台显示元/股 |
| `hk_connect` | 南向港股通，代码格式同港股，如 `09988` | 港股原币/股 |
| `us_stocks` | 美股，如 `AAPL`、`TSLA`、`BRK.B`；`BRK-B` 自动规范为 `BRK.B` | 美元/股 |
| `crypto` | 现货交易对，如 `BTC/USDT`、`ETH-USDT`、`BTCUSDT`，均规范为斜线形式 | 按交易对显示，例如 USDT/BTC；USDT 不当作美元 |

不关注的字段可以省略或填 `[]`。提供了 JSON 配置后，仅关注其中明确列出的品种；只填 `us_stocks` 就只关注美股。加密货币需填写完整交易对，单独 `BTC` 会报错；交易对必须在来源交易所现货市场存在。示例仅用于说明格式，不代表投资推荐。

需要设置显示名称或暂停某个品种时，所有市场均可使用以下对象格式：

```json
{
  "gold": [
    {"symbol": "Au99.99", "name": "上金所黄金", "enabled": true}
  ],
  "stocks": [
    {"symbol": "sh600519", "name": "贵州茅台", "enabled": true},
    {"symbol": "sz000001", "name": "平安银行", "enabled": true},
    {"symbol": "bj920002", "name": "万达轴承", "enabled": false}
  ]
}
```

股票是示例，可替换为你关注的代码。`enabled: false` 暂停该品种；删除条目或设为空数组也可以。未设置任何配置时，默认只关注 `Au99.99`，不会自动关注示例股票。

A 股和 ETF 代码必须使用字符串，支持六位代码、市场前缀、市场后缀格式，例如 `000001`、`sz000001`、`000001.SZ`，以及 `510300`、`sh510300`、`510300.SH`。A 股沪市以 `6` 开头，深市以 `0`、`3` 开头，北交所以 `4`、`8`、`92` 开头；ETF 支持沪市 `51`、`52`、`53`、`56`、`58` 开头及深市 `159` 开头的代码。市场前缀与代码不一致会报配置错误；代码仍须对应来源存在的实际证券。未填写名称时，尽量从数据源获取，失败时仍显示代码。

国内 ETF 直接加入 `stocks`，无需新增配置字段或依赖，例如只关注沪深300、创业板、黄金和纳指 ETF：

```json
{"stocks": ["510300", "159915", "518880", "513100"]}
```

推送的是 **ETF 场内成交价格**，单位为**元/份**，保留三位小数，涨跌幅相对前一交易日收盘价。不是基金净值、IOPV 估值或折溢价。黄金、跨境及港股主题 ETF 也按沪深交易时段推送，不跟随上金所夜盘或境外市场时段；休市时手动运行会显示最后可用报价。国内 ETF 固定使用腾讯单品种免费行情；`stock_source` 仅控制 A 股个股。当前不提供场外基金净值、ETF 联接基金或 LOF 的订阅。

黄金还支持同属上金所、按元/克计价的 `Au99.95`、`Au100g`、`Au99.5`、`iAu99.99`、`iAu99.5`、`iAu100g`、`Au(T+D)`、`mAu(T+D)`、`Au(T+N1)`、`Au(T+N2)`；不接受国际黄金、积存金或金店价格代码，避免混淆报价口径。

如果更习惯文件配置，可以复制 `market-alert.example.json` 到自己的持久化路径，将 **`MARKET_ALERT_CONFIG_FILE`** 设为其绝对路径。这两个配置环境变量只能选一个。示例文件不会随入口脚本自动复制到青龙。

## 数据源与时效

| 市场 | 主要来源 | 备用方式 |
| --- | --- | --- |
| A 股个股 | AKShare → 东方财富单股票报价 | `auto` 模式下故障切换腾讯公开行情；本轮剩余股票直接用腾讯，避免反复请求故障源 |
| 国内 ETF | 腾讯公开单品种行情 | 失败时说明原因，其余品种继续；沿用沪深交易日历 |
| 黄金 | AKShare → 上金所公开分时行情 | 适配失败时尝试直接读取上金所同一合约的公开分时数据 |
| 港股、港股通、美股 | 腾讯公开单品种行情 | 失败时说明原因，其余品种继续；不遍历下载全市场股票 |
| 加密货币现货 | Binance 公共市场数据域名单交易对 24h ticker | 失败时尝试 OKX 同名现货交易对，并标明来源变化 |

AKShare 是数据获取工具。国内 ETF 使用腾讯单品种报价，避免 AKShare 个股接口将沪市 `5` 开头代码映射到深市，也避免每次扫描全市场 ETF。港股、美股采用腾讯单品种报价，避免 AKShare 全市场接口的分页扫描；AKShare 的新浪美股列表接口还明确注明有 15 分钟延迟。腾讯免费行情同样没有固定实时性或延迟承诺。

加密货币使用无需 API Key 的公开行情，只取价格，不需要交易账户；Binance/OKX 的网络可达性取决于青龙服务器所在地区。不更换交易对的计价币种；备用源对应另一家交易所，实际价格可能不同，消息会标明。两家都无法访问或都没有该交易对时，消息显示错误。

免费行情没有固定秒级延迟或可用性保证，脚本在每次推送前取价。黄金备用方式仍依赖上金所，源站整体不可用时也会失败。股票备用使用腾讯公开行情，未找到稳定性或延迟承诺。

消息包含来源、获取时间，以及数据源提供的行情时间。东方财富的 AKShare 单股票报价接口不返回行情时间，消息会明确标注“无法核实延迟”；腾讯和上金所提供时间时，据此检查新鲜度。超过默认 10 分钟会标注“行情延迟”；开盘尚未产生新报价时，会标明上一时段价格。未来时间、零值、空数据、非数字不会作为正常黄金现价使用。价格未变化本身不代表行情过期。

上金所夜盘响应中的日期可能使用交易日，例如周一晚上标为周二、周五晚上标为下周一。脚本根据当前夜盘起止时间换算为实际北京时间，再选择最新分时价格并检查延迟；换算后仍晚于当前时间的报价才会作为异常拒绝。

股票、国内 ETF 和黄金的涨跌幅相对**前一交易日收盘价**；加密货币明确标为**滚动 24h 涨跌幅**。加密货币的行情时间是来源统计窗口截止或快照生成时间，不代表最后成交时间，流动性不足时需留意。价格保留来源的十进制精度，低价币不会简单四舍五入为零。黄金夜盘属于下一个交易日，前收盘价按交易日计算并缓存；无法取得前收盘价时显示“暂无”，不影响现价推送。单个品种失败时在消息中标明，其余照常发送；本次任务退出码为 1，便于在青龙日志中发现异常。

## 可选配置

以下字段放在同一个 JSON 配置对象中，完整示例见 `market-alert.example.json`。

| 字段 | 默认值 | 用途 |
| --- | --- | --- |
| `stock_source` | `"auto"` | 仅控制 A 股个股：`auto` 优先 AKShare，失败切换腾讯；`akshare` 仅用 AKShare；`tencent` 直接用腾讯。国内 ETF、港股、美股固定使用腾讯 |
| `timeout_seconds` | `10` | 单次网络连接/读取超时上限，允许 1—60 秒；多次请求的总耗时可能更长 |
| `stale_minutes` | `10` | 行情延迟提示阈值，允许 1—120 分钟 |
| `calendar_overrides.a_share.closed_dates` | `[]` | A 股及国内 ETF 额外休市日期，格式 `YYYY-MM-DD` |
| `calendar_overrides.a_share.open_dates` | `[]` | 明确覆盖为开市的日期 |
| `calendar_overrides.sge.closed_dates` | `[]` | 上金所额外休市日期，也会影响前一晚夜盘判断 |
| `calendar_overrides.sge.open_dates` | `[]` | 上金所明确开市日期 |
| `calendar_overrides.sge.no_night_dates` | `[]` | 取消夜盘的**开始日期**，例如周五填周五日期，其周六凌晨也不推送 |
| `calendar_overrides.hk_share` / `.hk_connect` | `{}` | 可设置 `closed_dates`、`open_dates`、`half_days` 日期数组；半日市至 12:00，港股与港股通分别设置 |
| `calendar_overrides.us_share` | `{}` | 可设置 `closed_dates`、`open_dates`，日期按纽约当地交易日；额外开市采用当地 09:30—16:00 |

运行状态默认写在脚本同目录的 `.market-alert/`。可以设置 **`MARKET_ALERT_STATE_DIR`** 指向青龙可写的持久化目录。请保留该目录并让同一任务使用同一路径，以保留播报去重、股票名称、黄金前收盘价及年度日历缓存。任务持有文件锁，避免并发重复推送；面板通知返回成功后才记录时点，失败时不占用记录。旧版脚本通知模块返回 `None` 时只能确认调用完成，日志会明确说明未确认送达。

## 本地验证

```bash
python -m venv .venv
# 激活虚拟环境后
python -m pip install -r requirements.txt
python tests/test_market_alert.py.test -v
```

开发测试使用 `.py.test` 后缀，避免青龙把它识别为订阅任务；直接交给 Python 运行即可。GitHub Actions 会运行同一套测试，并检查仓库只有一个可订阅脚本。

只检查配置和某一时刻的交易状态，不取价、不通知：

```bash
python market_alert.py --check --now 2026-11-16T10:00:00
python market_alert.py --check --now 2026-11-14T01:30:00
```

在交易时段预览真实取价，或在休市时强制检查数据源：

```bash
python market_alert.py --dry-run
python market_alert.py --dry-run --force
```

`--dry-run` 不通知、不写入运行状态，也不会消耗该时点的推送记录。`--force` 忽略交易时段和已推送状态；不加 `--dry-run` 会真实调用青龙通知。半小时频率交给青龙定时任务，脚本不再按分钟拦截，避免手动执行或队列延迟时无法取价。`--now` 只可用于检查和预览，行情仍是数据源当前返回的数据，**不会回放历史行情**。

休市时，正常定时执行应只看到休市跳过日志，青龙面板手动执行则会检查行情及通知。命令行手动排查可以使用 `--force`。免费源在休市时可能返回上次报价或异常时间；交易时段中的延迟、黄金夜盘和青龙渠道最终送达，需要在部署后的实际开市时验证。

## 常见问题

### 已在使用旧版，如何增加国内 ETF、港股、美股或加密货币

1. 在「订阅管理」执行一次订阅，拉取更新；原有 `market_alert.py` 任务继续使用，名称仍为「黄金与A股行情播报」，无需新建任务。
2. 要启用美股，在「依赖管理 → Python3」额外安装 `exchange-calendars==4.13.3`。只新增国内 ETF、港股、港股通或加密货币则无需安装它。
3. 修改原有 `MARKET_ALERT_CONFIG`，添加所需关注列表，直接点击行情任务「运行」检查所有品种及通知。

新增境外市场或加密货币时，消息标题显示「多市场行情」；只有黄金、A 股及国内 ETF 时显示「黄金与A股/ETF行情」，未配置 ETF 的旧版标题保留。定时规则仍为 `0,30 * * * *`。

### 交易日没有推送、手动运行被时间限制拦截

先重新执行订阅拉取更新，再直接点击「黄金与A股行情播报」的「运行」。新版启动日志包含 `v2026.11.19.2`，不会再出现“不是整点/半点，本次跳过”。

日志依次输出 `[启动]`、`[调度]`、`[日历]`、`[取价]`、`[通知]` 和 `[完成]` 或 `[失败]`，可区分没有调度、休市跳过、行情失败和通知失败。手动执行会尝试只读检查青龙中的实际定时规则，读取不到时也会继续检查行情和通知。HTTP 错误会显示来源主机和状态码，超时或缺依赖会显示具体类型，不打印通知密钥和代理密码。

如果更新后仍未自动触发，请检查**行情任务自身**是否启用、定时规则是否为 `0,30 * * * *`。订阅更新只负责拉代码，不保证覆盖已有任务的规则。代码同时提供 `cron:` 和带文件名的定时注释，兼容不同版本的青龙；已有的错误规则需要在该任务中改正一次。

如果日志显示 `QLAPI.systemNotify` 返回 `code=400`，到青龙「系统设置 → 通知设置」发送测试通知，检查接收账号及渠道配置。只有 `code=200` 时脚本才记录面板确认成功，未返回结果不会被当作面板发送成功。

### 旧订阅中出现了测试任务

早期版本中的 `tests/test_market_alert.py` 可能被青龙误添加为任务，并出现 `ModuleNotFoundError`。当前仓库已调整测试文件后缀，默认订阅只会添加 `market_alert.py`，不需要配置过滤规则。

已有订阅更新时：

1. 重新执行订阅，拉取更新。如果之前填写过白名单、黑名单，可以清空。
2. 在「定时任务」中停用或删除命令含 `tests/test_market_alert.py` 的旧任务，只保留「黄金与A股行情播报」。这是旧版本的一次性清理；未开启自动删除任务的青龙可能保留旧任务。

正式任务命令通常为 `task whwnow_qinglong-market-alert/market_alert.py`，目录名如设置了订阅别名，以实际目录为准。
