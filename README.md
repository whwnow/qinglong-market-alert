# 青龙黄金与 A 股行情订阅

在各自的交易时段，每半小时获取一次关注品种的最新行情，通过青龙已配置的通知渠道发送。黄金默认使用上金所 Au99.99，报价单位为人民币元/克；股票支持沪、深、北 A 股。同一时点合并为一条消息。

首次使用只需安装依赖、添加仓库订阅；关注 A 股时再配置关注列表。**白名单、黑名单和依赖文件均可留空**，仓库只有一个会被青龙默认识别的脚本，自动生成一个行情任务。

## 推送规则

所有时间均为北京时间，开盘、收盘时点也会播报。

| 市场 | 时段 | 推送频率 |
| --- | --- | --- |
| A 股 | 09:30—11:30、13:00—15:00 | 每半小时一次，共 10 次/交易日 |
| 上金所黄金日盘 | 09:00—15:30 | 每半小时一次，共 14 次/日盘 |
| 上金所黄金夜盘 | 20:00—次日 02:30 | 每半小时一次，共 14 次/夜盘，凌晨照常 |

A 股午休或收盘后，只播报当时仍在交易的黄金。均已休市时，不获取行情、不发通知。正常周五的夜盘延续至周六 02:30，周日晚上不开夜盘；法定节假日前的停夜盘日期单独处理，行政补班周末也不会误判为交易日。

内置两家交易所公布的 **2026 年**日历。其他年份会尝试读取各自官网的全年休市公告，识别成功后缓存。官网尚未公布、访问失败或页面格式改变时，该市场暂停播报，并在日志说明原因；其他可确定开市的市场继续播报。日历不会退化为简单的周一至周五判断。特殊临时休市可以通过配置覆盖；已缓存年度日历发生变更时，需更新覆盖配置或删除对应缓存后重新获取。

## 在青龙中使用

### 1. 安装 Python 依赖

需要 **Python 3.11.5 或更高版本**。在青龙「依赖管理 → Python3」中分别添加并安装：

```text
akshare==1.20.63
requests>=2.32,<3
```

安装成功后再运行行情任务。AKShare 依赖 pandas 等组件，首次安装可能需要一些时间。仓库中的 `requirements.txt` 用于本地或终端安装，订阅本身不会自动安装 Python 依赖。

### 2. 添加仓库订阅

在青龙「订阅管理」中新建公开仓库订阅，填写仓库链接：

```text
https://github.com/whwnow/qinglong-market-alert.git
```

保持自动添加任务开启，白名单、黑名单、依赖文件和分支留空，其余使用默认值即可。如果面板要求填写文件后缀，填 `py`。

保存后执行一次订阅，会自动创建「黄金与A股行情播报」任务。时间规则已经写在脚本中，无需手动创建任务或填写运行命令：

```cron
0,30 * * * *
```

每小时的 00、30 分运行，脚本自动跳过休市时段。订阅自身的更新频率可以保持你平时使用的设置，它只负责拉取代码。请确认青龙系统时区为 **Asia/Shanghai**，通知渠道已配置可用。

使用青龙任务执行器运行脚本，让青龙注入通知能力。脚本优先使用 `QLAPI.notify`，兼容 `__ql_notify__.send` 和已存在的 `notify.send`。通知渠道仍在青龙里配置，不用在本项目填写推送密钥。

### 3. 配置关注品种

默认只关注 Au99.99，不需要填写配置。要关注股票，在青龙环境变量中添加 **`MARKET_ALERT_CONFIG`**，值例如：

```json
{"gold": ["Au99.99"], "stocks": ["600519", "000001"]}
```

股票代码替换成自己的关注列表即可。不要加 `export`，不要在最外层再包一层引号。需要设置显示名称或暂停某个品种时，可以使用完整格式：

```json
{
  "gold": [
    {"symbol": "Au99.99", "name": "上金所黄金", "enabled": true}
  ],
  "stocks": [
    {"symbol": "sh600519", "name": "贵州茅台", "enabled": true},
    {"symbol": "sz000001", "name": "平安银行", "enabled": true},
    {"symbol": "bj920002", "name": "万达轴承", "enabled": false}
  ]
}
```

股票是示例，可替换为你关注的代码。`enabled: false` 暂停该品种；删除条目或设为空数组也可以。未设置任何配置时，默认只关注 `Au99.99`，不会自动关注示例股票。

股票代码必须使用字符串，支持 `000001`、`sz000001`、`000001.SZ` 三种格式。沪市以 `6` 开头，深市以 `0`、`3` 开头，北交所以 `4`、`8`、`92` 开头；市场前缀与代码不一致会报配置错误。未填写股票名称时，尽量从数据源获取，失败时仍显示代码。

黄金还支持同属上金所、按元/克计价的 `Au99.95`、`Au100g`、`Au99.5`、`iAu99.99`、`iAu99.5`、`iAu100g`、`Au(T+D)`、`mAu(T+D)`、`Au(T+N1)`、`Au(T+N2)`；不接受国际黄金、积存金或金店价格代码，避免混淆报价口径。

如果更习惯文件配置，可以复制 `market-alert.example.json` 到自己的持久化路径，将 **`MARKET_ALERT_CONFIG_FILE`** 设为其绝对路径。这两个配置环境变量只能选一个。示例文件不会随入口脚本自动复制到青龙。

## 数据源与时效

| 市场 | 主要来源 | 备用方式 |
| --- | --- | --- |
| A 股 | AKShare → 东方财富单股票报价 | `auto` 模式下故障切换腾讯公开行情；本轮剩余股票直接用腾讯，避免反复请求故障源 |
| 黄金 | AKShare → 上金所公开分时行情 | 适配失败时尝试直接读取上金所同一合约的公开分时数据 |

AKShare 是数据获取工具。免费行情没有固定秒级延迟或可用性保证，脚本在每次推送前取价。黄金备用方式仍依赖上金所，源站整体不可用时也会失败。股票备用使用腾讯公开行情，未找到稳定性或延迟承诺。

消息包含来源、获取时间，以及数据源提供的行情时间。东方财富的 AKShare 单股票报价接口不返回行情时间，消息会明确标注“无法核实延迟”；腾讯和上金所提供时间时，据此检查新鲜度。超过默认 10 分钟会标注“行情延迟”；开盘尚未产生新报价时，会标明上一时段价格。未来时间、零值、空数据、非数字不会作为正常黄金现价使用。价格未变化本身不代表行情过期。

涨跌幅相对**前一交易日收盘价**。黄金夜盘属于下一个交易日，前收盘价按交易日计算并缓存；无法取得前收盘价时显示“暂无”，不影响现价推送。单个品种失败时在消息中标明，其余照常发送；本次任务退出码为 1，便于在青龙日志中发现异常。

## 可选配置

以下字段放在同一个 JSON 配置对象中，完整示例见 `market-alert.example.json`。

| 字段 | 默认值 | 用途 |
| --- | --- | --- |
| `stock_source` | `"auto"` | `auto` 优先 AKShare，失败切换腾讯；`akshare` 仅用 AKShare；`tencent` 直接用腾讯 |
| `timeout_seconds` | `10` | 单次网络连接/读取超时上限，允许 1—60 秒；多次请求的总耗时可能更长 |
| `stale_minutes` | `10` | 行情延迟提示阈值，允许 1—120 分钟 |
| `calendar_overrides.a_share.closed_dates` | `[]` | 额外休市日期，格式 `YYYY-MM-DD` |
| `calendar_overrides.a_share.open_dates` | `[]` | 明确覆盖为开市的日期 |
| `calendar_overrides.sge.closed_dates` | `[]` | 上金所额外休市日期，也会影响前一晚夜盘判断 |
| `calendar_overrides.sge.open_dates` | `[]` | 上金所明确开市日期 |
| `calendar_overrides.sge.no_night_dates` | `[]` | 取消夜盘的**开始日期**，例如周五填周五日期，其周六凌晨也不推送 |

运行状态默认写在脚本同目录的 `.market-alert/`。可以设置 **`MARKET_ALERT_STATE_DIR`** 指向青龙可写的持久化目录。请保留该目录并让同一任务使用同一路径，以保留播报去重、股票名称、黄金前收盘价及年度日历缓存。任务持有文件锁，避免并发重复推送；只有通知调用成功后才记录时点。通知模块返回 `None` 时只能确认调用完成，渠道最终送达需查看青龙通知日志。

## 本地验证

```bash
python -m venv .venv
# 激活虚拟环境后
python -m pip install -r requirements.txt
python tests/test_market_alert.py.test -v
```

开发测试使用 `.py.test` 后缀，避免青龙把它识别为订阅任务；直接交给 Python 运行即可。GitHub Actions 会运行同一套测试，并检查仓库只有一个可订阅脚本。

只检查配置和某一时刻的交易状态，不取价、不通知：

```bash
python market_alert.py --check --now 2026-11-16T10:00:00
python market_alert.py --check --now 2026-11-14T01:30:00
```

在交易时段预览真实取价，或在休市时强制检查数据源：

```bash
python market_alert.py --dry-run
python market_alert.py --dry-run --force
```

`--dry-run` 不通知、不写入运行状态，也不会消耗该时点的推送记录。`--force` 忽略时段和半小时限制；不加 `--dry-run` 会真实调用青龙通知。`--now` 只可用于检查和预览，行情仍是数据源当前返回的数据，**不会回放历史行情**。

今天休市时，正常运行应只看到休市跳过日志。免费源在休市时可能返回上次报价或异常时间；交易时段中的延迟、黄金夜盘和青龙渠道最终送达，需要在部署后的实际开市时验证。

## 常见问题

### 旧订阅中出现了测试任务

早期版本中的 `tests/test_market_alert.py` 可能被青龙误添加为任务，并出现 `ModuleNotFoundError`。当前仓库已调整测试文件后缀，默认订阅只会添加 `market_alert.py`，不需要配置过滤规则。

已有订阅更新时：

1. 重新执行订阅，拉取更新。如果之前填写过白名单、黑名单，可以清空。
2. 在「定时任务」中停用或删除命令含 `tests/test_market_alert.py` 的旧任务，只保留「黄金与A股行情播报」。这是旧版本的一次性清理；未开启自动删除任务的青龙可能保留旧任务。

正式任务命令通常为 `task whwnow_qinglong-market-alert/market_alert.py`，目录名如设置了订阅别名，以实际目录为准。
